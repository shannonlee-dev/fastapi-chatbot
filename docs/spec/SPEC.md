# AI 챗봇 서비스 명세

이 문서는 프로젝트의 제품·system 요구사항과 세부 기술 계약의 index를 제공합니다. 구체적인
HTTP, 영속 저장, 모듈 인터페이스, 프런트엔드, 실행·배포 계약은 각 소유 문서에서 정의합니다.

## 1. 목표

팀 단위로 Linux, 웹, DB, AI API를 통합한 웹 기반 AI 챗봇을 개발하고 배포한다.

## 2. 최종 결과물

- 정상 동작하는 FastAPI 웹 애플리케이션 1개
- 운영 환경에서 외부 네트워크로 접속 가능한 서비스 URL
- GitHub 저장소 링크와 검증 가능한 문서 package

## 3. 기술 계약 안내

- 애플리케이션은 Python과 FastAPI 기반의 모듈형 모놀리식 구조로 구성합니다.
- 대화 기록은 운영자가 확인할 수 있는 영속 저장 storage에 저장합니다.

## 4. 기능 요구사항

### 4.1 웹 UI

- 사용자가 텍스트 질문을 입력할 수 있어야 한다.
- 질문 제출 후 같은 화면에서 AI 응답을 확인할 수 있어야 한다.
- 화면 구조, 브라우저 상태, 상호작용, 접근성, 반응형 동작은
  [프런트엔드 UI 계약](ui/UI.md)을 따른다.

### 4.2 인증과 접근 제어

- 회원가입과 로그인이 정상 동작해야 한다.
- 인증 상태에 따라 접근 가능한 기능을 구분해야 한다.
- 챗봇 질문·응답 기능은 로그인한 사용자만 사용할 수 있어야 한다.

### 4.3 AI 챗봇

- 서버가 질문을 수신하고 AI API를 호출해 응답을 생성해야 한다.
- AI API 호출과 인증 정보 처리는 서버에서 수행하고, 클라이언트에는 결과만 반환해야 한다.
- 사용자 또는 세션의 이전 대화를 활용하는 문맥 유지 전략을 적용해야 한다.

### 4.4 대화 로그

- 사용자 질문과 AI 응답을 DB에 누적 저장해야 한다.
- 사용자 식별자, 생성 시각, 질문, 응답을 필수로 저장해야 한다.
- 사용자 기준으로 대화 로그를 조회하고 추적할 수 있어야 한다.

### 4.5 입력과 오류 처리

- 사용자 입력 검증을 1개 이상 적용해야 한다.
- AI API 호출에 시간 제한을 설정해야 한다.
- AI API 실패나 시간 제한이 발생해도 서비스가 비정상 종료되지 않아야 한다.
- 오류 발생 사실을 메시지, 상태 코드 또는 안내로 사용자에게 전달해야 한다.

## 5. 운영 요구사항

서버 로그에 다음 이벤트와 성공·실패 여부를 기록해야 한다.

- 요청 수신
- AI API 호출
- AI API 응답 수신 또는 실패
- DB 저장

## 6. 보안과 설정 관리

- API 키와 DB 비밀번호 등 민감정보를 코드와 문서에 직접 작성하지 않는다.
- 민감정보는 환경 변수로 관리한다.
- `.env`는 `.gitignore`로 저장소에서 제외한다.
- `.env` example 파일을 제공한다.
- README에 환경 변수 이름과 설정 방법을 작성한다.

## 7. 배포 요구사항

- 배포된 서비스를 외부 네트워크에서 사용할 수 있어야 한다.
- 실행, 배포, 환경 변수 설정은 [실행·배포 계약](DEPLOYMENT.md)을 따릅니다.

## 8. 협업과 형상관리

- 저장소의 Git 및 GitHub 규칙에 따라 브랜치를 운영한다.
- 기능 단위 작업 브랜치 기록을 남긴다.
- PR 기반 병합 기록을 남긴다.
- 팀 역할과 개인별 작업 요약은 Git 이력과 일치해야 한다.

README 또는 기술 문서에 다음 내용을 포함해야 한다.

- 문제 정의, 대상 사용자, 핵심 scenario를 포함한 프로젝트 개요
- system 구조와 주요 구성요소 역할
- 요청·응답 예시를 포함한 API spec

- 실행·배포 방법과 환경 변수 설정 방법
- 팀 구성원 역할과 개인별 작업 요약
- `.env` example과 `.gitignore` 적용 방법을 포함한 민감정보 관리 방법

- 확인용 SQL, 스크립트 또는 증빙 자료 링크
